# Format: Written Post

Text-first content: LinkedIn posts, Facebook posts, X threads, and standalone captions. Uses ONE hook layer, written/, but uses it twice: the opener (the hook) and the structure of the whole post (formatting IS the visual layer here).

## The two hook slots

1. **The opener** (written/patterns.md, same goal as the post): the first line, written to survive the platform's fold. Everything before "see more" is the entire ad for the post.
2. **The re-hook rhythm**: long posts apply verbal/structure.md's logic in text. A turn, receipt, or open loop every 3 to 5 lines, different type each time, because scanners bail at the first flat stretch.

## Platform fold rules (from the rubric, the numbers that matter)

- **LinkedIn:** ~210 characters visible on desktop, ~140 on mobile. Write the hook to work at 140. A paragraph break ends the preview snippet, so the opener runs as an unbroken line to the fold.
- **Facebook:** truncation varies ~280-477 characters; aim the hook at 80 so it never gets cut anywhere.
- **Instagram caption as the post** (photo-plus-long-caption format): hook inside ~125 characters.
- **X/threads:** the first post is the cover; the keyword-scaling rule applies in miniature, put the power word in the first 5 words.

## The Kyndle LinkedIn system (locked, this file serves it)

The existing three-skill pipeline (ideation > post writing > image brief) and the Pierre Herubel-style framework govern LinkedIn output: one sentence per line, scannable, 3rd-grade reading level enforced per sentence, operator-observation hooks validated against real discovery-call experience. This format file adds the hook engine underneath it:

- Operator observations ARE verbal patterns in written form: the Proxy Open (a client's story), the Receipt Drop (a number from a real audit), the Diagnosis (the pattern behind the calls). Pull from the goal section, then voice it as an observation.
- The one-sentence-per-line format is the written re-hook system: each line is a beat, and every 3 to 5 beats needs a turn.
- The 3rd-grade reading rule matches the rubric's clarity criterion and the "dumbify" principle from the slide research: simpler language, less mental load, wider spread.

## Assembly sequence

1. Goal and topic, then TWO questions before anything is written:
   - "Which platform is this for?" (LinkedIn, Facebook, X, or Instagram caption-post; the platform sets the fold rules below)
   - For LinkedIn and Facebook: "Want the companion image created with this post?" Default is to offer it every time; on yes, run the Companion Image section below alongside the post.
2. Opener from the goal's written section, drafted for the chosen platform's fold (and at the other lengths if cross-posting). Grade; first three words checked as their own mini-hook.
3. Body: one idea per line-block, a re-hook every 3 to 5 lines (receipt, turn, question, anti-example), white space as the pacing device. Selective bolding does NOT exist on LinkedIn; line position does that work instead: the most important line stands alone.
4. The close: resolve the loop, then the ramp. On LinkedIn the comment-keyword mechanic works but DM-gating reads spammier than on Instagram; the verified alternatives are the direct question close (drives comments) or the profile-visit close (authority goal).
5. Caption-splitting rule does not apply here; the post IS the caption. But the FIRST COMMENT is a real slot: links live there, never in the post body.
6. Grade against the rubric; ramp check; ship.

## The companion image (the cousin)

The image that rides WITH a LinkedIn or Facebook text post. The post is the primary hook and pays the value; the image has exactly two jobs: stop the scroll before line one gets read, and survive alone (screenshot-shareable, fully understandable without the post).

**Selection, matched to the post's engine (same goal, per the stacking rule):**
- Post built on one provocative claim > statement card carrying that claim, WORDED DIFFERENTLY than the opener
- Post built on a number > stat graphic, source named small
- Post built on a list or framework > one-frame framework card: the post compressed into a savable receipt
- Topic that literalizes well > embodied-metaphor scene from the Concept Engine
All four types and their layouts live in formats/graphic.md and visual/styles/.

**Rules:**
1. Non-redundancy: the image never repeats the opener verbatim. Text claims; image shows, compresses, or embodies. Redundancy wastes the slot.
2. Standalone test: shared without the post, the image still works. This is what makes it save-worthy.
3. Kyndle climates and type (luminance rule, Balboa + Shadows Into Light via the hybrid path), 4:5 portrait, one focal element, 3-Second Test applies.
4. NO magazine metadata strip (that dressing is carousel identity); a small handle mark only.
5. NO ramp inside the image; the ramp lives in the post and the first comment.
6. Producer: the existing Kyndle image-brief skill, now fed its brief by these systems (type, climate, text, scene) instead of improvising.

## Written-post-only mechanics

- **The fold test:** paste the opener into a 140-character counter. If the claim isn't complete by the cutoff, rewrite; a cliffhanger cut mid-setup reads as an accident, a cliffhanger cut mid-tension reads as a hook.
- **Line-block shape is scannable proof:** numbered stacks, arrow lines (>), and short contrast pairs (Old way: / New way:) are the written layer's diagrams.
- **The receipt placement rule:** at least one concrete number in the first 5 lines. Posts that open with philosophy and save proof for the end die at the fold.
- **Repost rule applies:** a flopped post likely wasn't distributed. Rewrite the opener, repost the body, per the verified 150.2x principle.
- **Cross-post discipline:** the same idea on LinkedIn and Instagram gets DIFFERENT openers (each platform's fold and audience), same goal. One idea, two written hooks, logged once in the swipe file.

## Grading checks specific to written posts

Before posting: opener survives the 140 fold with tension intact; first three words graded; a number appears in the first 5 lines; a re-hook lands every 3 to 5 lines; links in first comment only; ramp named or its absence deliberate. Two failures = back to assembly.
